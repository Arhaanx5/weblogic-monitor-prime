The Legacy Challenges

Why Traditional Browser Extensions Fail in Production

❌ Technical Bottlenecks of Legacy Systems

Active Tab Scraper Dependency: Older monitor tools worked by injecting scripts to scrape DOM elements of active WebLogic tabs. If an engineer closed the tab or navigated away, the socket scrape loop crashed immediately.

Chrome Inactive Tab Throttling: To optimize battery, Chromium enforces a strict power-saving policy. Inactive background tabs are throttled to a 60-second execution limit. This meant 3-second live timers lagged by over a minute.

Operational Impact: Delayed incident detections, false critical alerts during network drops, and high browser CPU load from repeatedly parsing heavy DOM trees.

🟢 How Prime v3.0 Restructures the Engine

Decoupled Memory Polling: We completely decoupled the scraping loop from active tabs. The extension now requests WebLogic server table HTML programmatically inside background threads using pure JS `fetch` queries.

Keep-Alive Heartbeat Drive: By utilizing Chrome’s official `offscreen` API, we run a low-level sandbox frame. This frame remains unthrottled by the browser, triggering background fetches every 3 seconds without interruption.

Operational Outcome: Zero open tabs required. Real-time metric streaming continues even when Chrome is minimized or the laptop is locked.

Under The Hood

Decoupled Architecture & Real-Time Flow

🏗️ High-Availability System Components

1. Offscreen Keep-Alive Engine: Runs a hidden HTML frame in the background. It executes a strict `setInterval` that sends a `POLL_NOW` message to the Service Worker every 3 seconds, bypassing background sleep.

2. Background Polling Service Worker: Listens to the keep-alive heartbeat, wakes up instantly, and fetches the specific WebLogic Server Table URL using the user's active session cookie.

3. Universal Stream Regex Decoder: Receives the fetched raw HTML string and extracts row metrics directly. It parses server names, health, and socket load in under 5 milliseconds.

State Synchronization: Once parsed, the State Aggregator triggers a unified state update to `chrome.storage.local` and broadcasts a sync message to update the NOC Dashboard and Popup widget.

📡 The Live Data Loop

The background poller does not scrap the graphical UI. It fetches raw text, which cuts down network packet sizes to less than 50KB.

This guarantees that even with 10+ WebLogic domains registered, the network bandwidth usage is negligible, making it enterprise-ready.

Result: Real-time socket metrics updates on the NOC wall screen every 3 seconds.

Robustness Design

Resilient Failover & Node State Preservation

🔐 Solving the Transient Disconnect Problem

The Problem: When WebLogic Admin Console performs session tree updates or user authorization shifts, background HTTP fetches may briefly redirect to login pages, returning empty responses or 302 redirects.

The Solution (Node State Preservation): If the universal parser receives 0 server nodes from a poll response, it does not wipe the dashboard. Instead, the Failover Guard locks onto the last-known active server nodes, health status, and socket counts.

Result: The dashboard continues to stream `🟢 LIVE (3s ago)` without graphical flicker or data loss. Once WebLogic recovers, the metrics merge automatically.

🔑 Session Expiry Detection

If the background HTTP response redirects to `LoginForm.jsp` (indicating the session cookie has expired), the background worker detects this immediately.

The worker marks the domain as logged out (`isLoggedOut = true`) without losing stored metric data.

Visual Indicator: An amber `🔑 SESSION EXPIRED` badge is rendered next to the domain. NOC engineers can click the `🔗 Switch Tab` button to re-login in 1-click.
🎙️ Speaker Script:
"To prevent layout flickering and data loss during WebLogic session refreshes, our Node State Preservation Guard locks onto cached metrics during empty responses and flags session timeouts with an amber indicator."
Alert Fatigue Mitigation

Intelligent Alerting: Hysteresis & VPN Protection

🚨 The Active Alerting & Health Matrix

The 70-Socket Warning Zone: 70 sockets is not the hard freezing point. Instead, it is a strict **Early-Warning Threshold** to keep NOC engineers active, alerted, and prepared for threat investigation.

The Actual Freezing Point (200 - 500+ Sockets): Sockets gradually increase under heavy loads; server hangs or thread freezes only occur when sockets breach the **200 to 500+ range**.

Compound Failure Trigger: Production trouble is signaled when **both** metrics degrade: socket counts breach the warning threshold, AND WebLogic health changes to `WARNING` or `FAILED` (`OVERLOADED` or `NOT REACHABLE`).

Hysteresis Zone: Siren triggers at >70 and clears strictly at <65 to prevent alarm toggling during small load oscillations.

📡 Silent VPN Protection

VPN Disconnection: Disconnecting from the corporate network blocks access to WebLogic IPs (`172.16.x.x`). Traditional monitoring registers this as a server crash and triggers sirens.

Our Solution: The background worker detects network unreachable exceptions, suppresses audio siren alerts (100% Silent), resets critical incident counters to 0, and flags cards as `📡 NETWORK DISCONNECTED`.

Auto-Recovery: Upon VPN reconnection, the poller automatically recovers to live monitoring state within 3 seconds.

Performance Optimization & Stream Decoding

⚡ The Universal Stream Regex Parser

No DOM Redraws: Traditional parsing creates a temporary DOM structure inside the extension page to query tables. This causes layout recalculation overhead.

Stream Parser: Our tool uses a streamlined, class-agnostic regex decoder that parses raw text sequentially. It extracts server names, health, and sockets in under 5 milliseconds.

Execution Overhead: Average CPU usage is 0.00%. The system runs seamlessly on standard corporate laptops.

📦 Network Bandwidth Optimization

By fetching text HTML instead of rendering console resources (CSS, JS, images), each background fetch payload is less than 50KB.

This minimizes network bandwidth overhead on corporate networks and VPN tunnels.

Memory Leak Protection: Service worker contexts are automatically recycled by Chromium, preventing long-term memory leaks.

Enterprise Privacy

Security Architecture & Compliance

🔒 100% Sandbox Isolation

Zero External Transmission: All scraped WebLogic server metrics, incident history logs, and settings remain inside the browser local sandbox (`chrome.storage.local` and IndexedDB). No data is sent to external servers.

Authentication Cookie Reuse: The background poller does not store user passwords. It uses Chrome's secure cookie container (`credentials: "include"`) to authenticate fetches with the active browser session.

Strict Content Security Policy: Fully compliant with Chrome Extension MV3 CSP guidelines. Zero remote script execution.

🛡️ Content Script Scoping

Content scripts are restricted in `manifest.json` to only match WebLogic ports (`:7001`, `:7002`) and console directories (`/console/`).

This ensures that the extension script is never injected into public pages like YouTube, GitHub, or search engines.

Security Status: Fully compliant with internal enterprise IT audits.
